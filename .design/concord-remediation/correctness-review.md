# Concord remediation correctness review

Reviewer: parent agent, after the requested Sol implementation and Daybreak Blue security review. Review date: 2026-09-06. Scope: the uncommitted remediation working tree against R01–R24, G01–G24 and F01–F26 in the controlling design. The baseline commit alone does not identify this implementation.

## Result

Verdict: **pass with documented qualification and dependency risks**. All coding is complete and all findings from the requested reviews are resolved. Final runtime validation found a local-avatar rendering defect and two qualification fixture defects; Sol repaired them and the parent verified the results. Strict Clippy also identified a manual ceiling-division expression in the qualification seeder; Sol replaced it with `usize::div_ceil`. No known unresolved implementation defect remains from these reviews. The separate release qualification items listed under limitations remain unverified.

The security review's one medium finding was repaired by Sol and re-reviewed by Blue before this review. Logout now reports a durable revocation failure, preserves the cookie on authority failure, and clears it only on successful revocation or an already-invalid credential. The default/all-feature real HTTP and live-WebSocket regression proves both the failed-write and successful-retry outcomes. See [the security report](security-review.md).

## Runtime findings

- CR-01 — Medium — Resolved: the profile/avatar browser journey received the committed `server_nickname_update` with a local media URL, but `MemberList` routed it through `ExternalImage`, whose HTTPS-only external URL parser returned no source for `/api/uploads/...`. Valid local avatars were hidden. The repaired `ExternalImage.tsx` and `externalUrl.ts` allow only the exact canonical local upload route directly and preserve third-party image consent and unsafe-URL rejection. Focused privacy regression, the real profile journey and all 51 browser harness tests pass. Blue rechecked this boundary and reported no new security/privacy finding.
- CR-02 — Low — Resolved: the restart browser journey asserted exactly one socket closure and two open attempts. A real reconnect attempt during the outage produced two closures. The corrected assertion observes one valid protocol-v2 `sync_snapshot` per application socket, verifies closure and a fresh snapshot after restart, and proves unreloaded Alice-to-Bob delivery, durable history after reload and credential revocation isolation. Its first attempted repair incorrectly waited for Vite's `connected` event; that failed run is retained. The corrected focused real test passed, followed by the parent full 20/20 authenticated suite.
- CR-03 — Low — Resolved: the real IRC runner invoked `browser_fixture_seed` without its newly required `CONCORD_FIXTURE_EXTERNAL_KEY_FILE`, despite already creating the correct private key file. It failed with `NotPresent` before client qualification. Sol bound that existing key; the other two callers already passed their corresponding keys. Shell syntax/ShellCheck passed, and the parent real-client rerun passed.

The first final authenticated run records 18 passes and the CR-01/CR-02 failures in `authenticated-browser.log`; the first IRC attempt records CR-03 in `irc-clients.log`. The intermediate 19/20 run is retained as `authenticated-browser-final.log`; the successful final 20/20 run is `authenticated-browser-complete.log`. Failed runs are retained rather than relabeled as passes.

## Invariants reviewed

| Area | Source and reasoning checked |
| --- | --- |
| Transactional acceptance | `engine/messaging.rs` validates current actor/resource authority in the admitted IMMEDIATE transaction. Message, sequence, attachment claims, receipt, event and external outbox are committed together. Success and wakeups follow commit. Existing receipts bind principal/client ID and payload fingerprint; retries return the canonical result, while conflicting reuse fails. AutoMod rejection commits only its intended moderation effects. |
| Admission and cancellation | `engine/write_admission.rs` shares bounded pending/active semaphores, applies the overall acquisition/BEGIN deadline, and returns owned permits. Cancellation drops queued admission and the transaction. Existing pool-exhaustion/locked-database regressions exercise recovery after failure. |
| Replay and current projections | `engine/replay.rs` binds encrypted cursors to database, credential, protocol and subscription identities. Authorization, retention boundaries and current entity projections are evaluated in the read transaction. The cursor advances past unrelated global events only after the selected page is exhausted. Snapshots bound messages, reactions and projected bytes and retain history boundaries. |
| Authorization and delivery | Actor services check resource ownership and policy; the transport boundary checker covers 59 production HTTP handlers/helpers and 124 WebSocket operations. `engine/user_session.rs` bounds both count and bytes and pairs each queued event with its guard under one lock. `web/ws_handler.rs` revalidates credentials/guards before serialization and bounds writes; overflow cancels the connection for recovery. Previously emitted bytes cannot be recalled. |
| Stable transport identity | `irc/framing.rs` retains partial reads across cancellation, bounds encoded lines and rejects partial EOF/invalid UTF-8. IRC adapters resolve stable identities and direct conversations through actor services. Runtime construction explicitly selects the TLS provider; connection shutdown owns its worker cleanup. |
| Browser state and recovery | `api/websocket.ts` detaches old socket callbacks and owns reconnect timers. Connection, pending, composer and entity stores separate ownership. Disconnect/account changes invalidate protected state and pending ownership. Correlated snapshots/replay use per-subscription cursors; command retries preserve their original durable identity. Lifecycle commands bound pending capacity and surface uncertain outcomes without automatic mutation replay. |
| Community and integrations | Reviewed integration handbacks and current regression evidence for transactional invite limits/rollback, announcement lineage across reopen/unfollow, roles/private threads, managed emoji/sticker revocation, canonical webhooks, installed bot scope/lifecycle, one-use interactions, delegated OAuth code/refresh reuse and explicit AT publication/reconciliation. Actual browser flows cover the F21–F24 lifecycle, including rejected input and retry. |
| Durable external jobs | `jobs.rs` claims with transaction/lease tokens, renews before dispatch, fences completion/retry against ownership, and bounds backoff. Runtime workers select their registered operation families. Webhooks claim one delivery per iteration; provider failures stay separate from core message acceptance. Restore pauses pending/leased work for reconciliation. |
| Restore and operation ownership | `operations.rs` canonicalizes database lock identity and refuses serving during an incomplete restore. `concord_operator.rs` binds the restore marker to backup/destinations, stages and verifies artifacts, changes generations, revokes web sessions and pauses external work before activation. Its copying/prepared phases support interrupted resume; the marker is removed only after activated-state verification. |
| Verification integrity | Reviewed nonempty suite selection, contract regeneration/runtime fixtures, immutable copied fixture binaries, isolated source-install provenance and load evidence classification. The final local load smoke records 45 telemetry samples, four concurrent staged uploads, restored canonical messages, an eligible reconciled webhook job, invalidated old session and zero final active connections/jobs/uploads. It explicitly does not claim the one-hour acceptance workload. |

## Limitations

The dedicated four-vCPU/eight-GiB host, separate generator and complete one-hour workload have not been run. Live third-party AT/OAuth/provider accounts, non-fixture outgoing receivers, interactive/manual client and accessibility qualification, production reverse-proxy deployment, physical power loss and other operating-system/filesystem behavior are not certified by local automated evidence. The tooling and declared acceptance thresholds remain in scope and have not been weakened.

The Rust dependency audit remains non-green: three vulnerability matches plus separately classified unsound/maintenance/yank warnings. Reachability and upstream constraints are documented in [dependency-audit.md](../../concord/docs/dependency-audit.md) and reviewed by Blue; no advisory suppression was added. These residual risks must remain visible to a release reviewer.

This is an evidence-based source review and executed regression assessment, not a formal proof or a claim to have exhaustively tested every possible race. No commit, push or deployment is part of this result.
