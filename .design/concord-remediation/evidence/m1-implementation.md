# M1 migration foundation implementation evidence

## Scope and schema decision

M1 reserves migration `017_migration_foundation.sql`. Migrations 001–016 remain byte-for-byte unchanged. The shared runner also registers migration 018, owned by the session-authority slice; M1's compatibility floor remains 17 and the current target is 18.

Migration 017 adds:

- `migration_metadata`: one SHA-256 and provenance value per recognized migration version. `adopted_release_effects` means a legacy database was matched to the release's complete schema fingerprint; it does not claim that the historical runner verified the bundled bytes. `bundled_script` means this runner executed the bundled script.
- `database_metadata`: the database generation UUID and minimum compatible schema version.
- `migration_repair_log`: durable object-level outcomes for deterministic repairs.
- `migration_snapshots`: pre-upgrade row counts captured under the exclusive migration lock.

The compatibility floor is 17. A binary that does not understand the M1 metadata and validation contract must not write a schema at or beyond this floor.

## Executable guarantees

`db/pool.rs` now:

1. Opens every pooled SQLite connection in WAL mode with `synchronous=FULL` and `foreign_keys=ON`, then reads both pragmas back and rejects the connection if SQLite did not apply them.
2. Acquires an SQLx-owned `BEGIN EXCLUSIVE` transaction before the final preflight. The transaction guard rolls back on error or cancellation.
3. Requires a recognized contiguous version history and compares the complete normalized `sqlite_schema` projection (tables, indexes, triggers, virtual-table artifacts, columns, constraints, and foreign-key SQL) with a pristine bundled fixture for the claimed source version. Normalization changes keyword/formatting case only outside quoted literals, so string-default changes remain detectable. Version 1 with the historical runner's ledger and the older unledgered form are accepted only when their respective full fingerprints match.
4. Validates stored SHA-256 values before re-entry at version 17.
5. Inventories existing foreign-key failures and the two known historical hazards before mutation. A populated/unknown migration-002 default-server orphan and an unresolved migration-014 user override return a concrete blocking report without changing authoritative data.
6. Captures pre-upgrade table row counts, runs each immutable bundled SQL file with `sqlx::raw_sql`, records the ledger, applies only the recognized empty generated-channel repair, rebuilds FTS, and runs `foreign_key_check` plus `integrity_check` before the single transaction commits.

The only automatic historical data removal is an empty `#general` or `#random` row generated by migration 002 whose `server_id='default'` has no server and which has no messages or members. Each removal is recorded. Populated or unrecognized rows require an operator mapping and are left unchanged.

## Verification

Focused tests cover fresh migration and three idempotent starts, checksum drift, noncontiguous history, quoted-literal-sensitive complete-schema drift, populated migration-002 orphan preservation/reporting, unresolved migration-014 override preservation/reporting, and populated upgrades from every source schema version 1–16. The file-backed integration fixtures preserve non-AT and AT identities, valid servers/private channels, message timestamps and literal entity/Markdown/Unicode bytes, reactions, attachment associations, user overrides, bots, and webhooks when the source version supports them.

Verification results:

- `cargo test -p concord-server --lib db::pool::tests --no-fail-fast`: **8 passed, 0 failed**.
- `target/debug/deps/migrations_upgrade-… --nocapture`: **1 passed, 0 failed**, executing all sixteen file-backed source-version fixtures against target 18, including timestamp/content/FTS/attachment and snapshot assertions.
- `cargo check -p concord-server --lib`: **passed** immediately before a concurrent configuration-module transition began.
- `cargo clippy -p concord-server --lib --all-features -- -D warnings`: **not completed in the final shared-tree state yet** because concurrent authorization edits left a transient parse error in `engine/chat_engine.rs` and dependent type errors in IRC/WebSocket code. The two M1 `collapsible_if` findings from the preceding run were repaired at their cause.
- `git diff --check -- server/src/db/pool.rs server/migrations/017_migration_foundation.sql`: **passed**.

The initial and final SHA-256 inventory confirms migrations 001–016 were not edited by this slice.

## Remaining gates

This evidence covers the M1 portion of R11/G11 and the database-pragmas portion of R05. It does not claim the later M2–M8 data repairs, storage power-loss fault injection, backup/restore qualification, or the full G11/G05 release gates.
